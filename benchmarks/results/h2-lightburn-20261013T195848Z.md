# H2 native export sizes and colours — 2026-10-13

Ten nested exports (five DXF, five SVG) open in **LightBurn Pro 2.1.01** without
warnings. The saved native geometry preserves each expected placed size within
**0.000033 mm**. CUT, COMMON, LEADIN and SHEET map to C00, C01, C02 and T1 in both
formats when tool-layer imports are enabled. All six final DXFs pass ezdxf 1.4.4
audit with **zero errors and zero repairs**.

This records the native export checks, not full H2 acceptance. Eight of ten
LightBurn size fields round to the analytic expected size. Both spline exports
display a width 0.003275 mm below the analytic width, although their saved curves
retain that width within 0.000002 mm. This display discrepancy is retained below;
we do not claim ten exact numeric-field matches or change the gate wording.

## Method and reproducibility

- [Preparation](h2-lightburn-20261013T195848Z/preparation.json) records source,
  label, binary, script and product-source hashes, licences, import options,
  placements and export hashes. Five fixed **training** cases were selected before
  reading their geometry/labels. No held-out geometry or labels were read.
- Each imported part has quantity two, with the default quarter-turn choices,
  2 mm spacing and 5 mm margins. All five layouts pass the independent validator.
  Expected dimensions come from independent analytic bounds of the exact imported
  curves after placement, including Bézier extrema and elliptical-arc extrema.
  They are not taken from re-imported exports or collision polygons.
- CLI preparation ran one suspended-then-affinity-pinned process on CCD0 core 0.
  The work budget was `--seconds 1 --repeatable`, with a 240 s cooperative limit
  and a 300 s external bound after the earlier timeout described below.
  This export check makes no speed or packing-quality claim.
- In the hidden Anode desktop (1920 × 1080, No Machine), each file was imported
  into an empty document, selected and measured in mm. No geometry, dimensions or
  import tolerance were edited. Native projects and full-resolution screenshots
  are retained for every measurement. Native import centres the drawing, so this
  check measures dimensions, not absolute workspace position.
- [Observed UI values](h2-lightburn-20261013T195848Z/native-observations.json) and
  [independent audit](h2-lightburn-20261013T195848Z/native-audit.json) are separate
  records. The unmodified published MIT `lbrn2-to-svg@0.5.3` reads the saved native
  projects; svgpathtools evaluates their curve extrema. These files contain only
  vector paths/ellipses, avoiding the known text/bitmap oracle limitations. The
  converter emitted no warnings. Native saved precision accounts for differences
  of up to 0.0000324 mm; this is below the plan's 0.01 mm fidelity tolerance.
- Reproduce preparation with `python scripts/h2_lightburn_prepare.py` after
  building the release CLI and `export_palette` example. Reproduce the independent
  audit with the pinned shop Python environment:
  `scripts/h2_lightburn_audit.py --results benchmarks/results/h2-lightburn-20261013T195848Z --output output/h2-native-audit-replay.json`.
  Use a new output path; previous audits are never overwritten.
- [Attribution](h2-lightburn-20261013T195848Z/LICENSES.md) applies to exports,
  native saves and screenshots. The authored palette coupon is MIT.

and 30, with index 30 of type Tool. Both coupons measure exactly 100 × 70 mm:
[DXF screenshot](h2-lightburn-20261013T195848Z/palette-dxf-native.png),

([screenshot](h2-lightburn-20261013T195848Z/settings-tool-import-enabled.png)),

([screenshot](h2-lightburn-20261013T195848Z/settings-tool-import-restored.png)).

setting off, SHEET can map to a cutting layer; this requirement is documented in
the import guide. The coupon's COMMON and LEADIN rectangles are authored colour
samples only. N4/N5 path generation is not implemented by this change.
