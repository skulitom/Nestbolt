# H3 missing text outlines: native repair evidence

This is a training-only diagnosis, not H3 acceptance. Eight frozen original
projects contain 122 Text objects without BackupPath. The current reader
preserves their XML and explicitly marks their geometry incomplete. Nesting
refuses incomplete movable text with instructions to open and re-save in
LightBurn. Two template projects keep the text fixed, but that does not prove
its geometry. The original-input geometry requirement remains unmet.

[LightBurn's text documentation](https://docs.lightburnsoftware.com/legacy/UI/FontsAndText)
explains that saved projects carry backup paths for portability when fonts are
unavailable. These originals specify Arial but contain no outline cache or
embedded font program. A font name alone cannot establish which font version
produced the original geometry across machines.

The existing frozen N0 native re-saves contain all 122 missing caches and
preserve all text strings. Nestbolt's reader matches the published MIT
lbrn2-to-svg@0.5.3 oracle for **477 leaves / 1,223 contours**, including all 122
Text leaves. Maximum bidirectional point difference is **0.000498792 mm**,
bounds **0.000499712 mm**, and image corners **0.000028008 mm**, below 0.01 mm.
All leaves are compared and no repaired shape is incomplete. The existing
oracle adapter is test-only; its normalization is documented in LBRN2.md.

## Limits and proposed treatment

Native Save As changes canonical CutSetting fields in all eight projects
(including legacy Scan+Cut to Scan in L42). These native files therefore are
auxiliary repaired inputs, never evidence that Nestbolt can replace or modify
the original document losslessly. Original source XML, labels, split and failed
geometry status remain authoritative and untouched. The repair does not solve
L17's independent zero-area open-path nesting issue or mixed fixed/active Groups.

A proposed H3 clarification is to retain byte-identical no-op preservation and
require a clear repair instruction for text without cached outlines; geometry
acceptance would apply after the user re-saves or converts text to paths.
This is **not approved** and is not used to mark H3 complete. It narrows the
literal requirement that every original shape match the oracle, even though
N2's reader specification explicitly describes Text through BackupPath.
