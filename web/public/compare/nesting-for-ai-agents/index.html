Nesting for AI agents: Nestbolt, OpenNest, pyFit, Sparrow and Deepnest compared

Reading the tools' repositories, three MCP directories and GitHub search on 2026-11-22, we found three open-source nesting tools that an AI agent can call over MCP, the same three as on 2026-10-20: Nestbolt (5 tools, SVG and DXF in), OpenNest by ajisaacs (19 tools in its v0.7.0 source and 33 on its master branch; DXF, DWG or SVG in; built from source) and pyFit (4 tools, a JSON job of polygons or single-loop DXF outlines, installed from source). Three hosted services now nest true shapes over MCP: SmartCut, CutOptim and NestSolver. Another tool with an MCP server, the desktop program nestpro, publishes its source under a small-business licence, not an open-source one. All three open-source ones also have command lines, as do nestpro, Sparrow, CLI-nesting (JSON polygons in) and sheetnest (DXF in), while Deepnest and SVGnest have none. In our run of 2026-11-22, three fresh Nestbolt v0.1.0 MCP servers nested the example job from its v0.1.0 source six times on one sheet (32 of 32 parts, checked by its validator) in 3.4 to 5.1 seconds per nest, and all six layouts were byte-identical, to each other and to the six from our first run on 2026-10-20 (method and data below).

We make Nestbolt. We ran only Nestbolt. Everything on this page about the other tools comes from their own repositories, documentation and release pages, read on 2026-11-22 at the commits linked below (and first on 2026-10-20), and is marked "from its docs". Hosted services were read from their public pages only. Last checked: 2026-11-22.

Nestbolt over MCP, measured

We downloaded nestbolt-v0.1.0-x86_64-pc-windows-msvc.zip from the v0.1.0 release (SHA-256 f3ba7548…167398, matching its SHA256SUMS) and drove nestbolt-mcp.exe over stdio with a small JSON-RPC client, the way an agent's MCP client does. Each of three runs started a fresh server in a new, empty workspace holding only examples/parts.svg from the v0.1.0 tag's source, with that tag's examples/nest-request.json (4 part shapes, 32 parts, one 600 × 400 mm sheet, 1 mm spacing). The release archive itself holds the two programs, licences, README and llms.txt, but no examples. The PC was an AMD Ryzen 9 7950X3D (16 cores) on Windows 11, and it was running other jobs at the time. This is the second run of the same steps: the first was on 2026-10-20, and v0.1.0 is still the latest release. The v0.1.0 server's own instructions already mention LightBurn input; Nestbolt's README documents LightBurn project nesting as a v0.2.0-alpha.1 preview feature.

Nestbolt v0.1.0 MCP server, three fresh runs, 2026-11-22 (every reply matched the 2026-10-20 run apart from its timings and folder paths, and every layout, SVG and DXF file was byte-identical; that run's timings are in the last paragraph of this section)

The command line gives the same result: nestbolt import parts.svg --output lib.json then nestbolt nest --library lib.json --request nest-request.json --out-dir run --seconds 10 --repeatable wrote the same 7fc2ed62… layout.json bytes as the MCP server in three runs, in 3.4 to 3.6 seconds each. Each tool call's arguments and reply, the tools/list reply, the progress notifications, the timings and the output hashes are in the data: run 1, run 2, run 3 and the CLI runs. The 2026-10-20 data is kept beside it (run 1, run 2, run 3, the CLI runs). Why a 10-second budget finished in about 3 to 5 seconds: Nestbolt's search contract spends half of time_budget_s (here 5 seconds) as deterministic work, estimated in seconds on one core of its reference CPU, the model this PC has. On 2026-10-20 that work took 3.1 to 3.9 real seconds on this job (first nests 3.1 to 3.2, repeats 3.6 to 3.9), so the work model's estimate ran high. On 2026-11-22, with other jobs running on the PC, the first nests took 3.4 to 3.8 seconds and the repeats 4.8 to 5.1, about the full 5 seconds; the full budget (at most 300 seconds) stays a hard real-time limit. A slower PC takes longer for the same layout, and if it hits the limit the reply says "repeatable": false.

Material use

We did not benchmark material use for this page. Nestbolt's README reports its frozen v1 benchmark (build 75cbb32, not the v0.1.0 binary measured above): 8.5% less material at the median than the best of Deepnest, SVGnest and Sparrow at equal 60-second budgets, with Sparrow winning 8 of 56 jobs. The Deepnest alternative guide explains that run and the results page has every number. OpenNest, pyFit, CLI-nesting, sheetnest and the other tools here besides Deepnest, SVGnest and Sparrow were not in that benchmark, so nothing here says which of them uses less material.

The other tools, from their docs

OpenNest

A Windows desktop app for CNC nesting on material plates that imports DXF, DWG and SVG and exports DXF, SVG, or G-code through post-processors. Its OpenNest.Mcp project is a stdio MCP server. In the v0.7.0 source it has 19 tools, among them import_dxf (which now also takes DWG and SVG), create_drawing (a built-in shape or a G-code string), create_plate, autonest_job, check_overlaps, plan_cutting and save_nest. Its master branch has 33: the 14 added on 2026-11-19, such as search_drawings, make_nests and renest_nest, work only when OpenNest is connected to its own nest server. Over MCP an agent brings DXF, DWG or SVG in and saves .nest files; no MCP tool exports DXF, SVG or G-code, and the console adds post-processed CNC output. Its README says the desktop, console, MCP and API nesting share an independent validation pipeline. The v0.7.0 release, published 2026-11-17, ships the desktop app as a ZIP, a self-updating Setup.exe and a portable ZIP; v0.7.0 also added SVG import and export, irregular sheet outlines for remnants and common-line cutting, which its notes say is not yet proven on a machine. The console and MCP server are built with the .NET 8 SDK, and its README says the console and API also build on Linux and macOS (from its docs, not run by us). A different project, petrasvestartas/OpenNest, shares the name.

pyFit

A Python package with a pyfit CLI and a pyfit-mcp stdio server whose four tools (design_nest, preview_nest, get_nest_report, export_nest) share one schema: sheet width and height, parts, and a rotation step. It fills several rectangular sheets, going back to scrap on earlier sheets before opening a new one, re-checks every candidate placement for overlap and containment, can return preview images into the conversation, and sends progress notifications. It has no spacing or kerf setting in its code, its DXF reader takes one closed loop of LINE entities per file, and its README says the package targets convex and simple shapes. Its README installs from PyPI, but that name returned 404 on 2026-10-20 and again on 2026-11-22, so it installs from source (from its docs, not run by us).

SmartCut

A hosted cut-list and nesting service with a REST API and an MCP endpoint at api.smartcut.dev/mcp. Both need an API key and an active subscription; its pricing page renders prices with scripts, so we could not read them as text. Its nesting mode takes part outlines with holes, which are cut but not filled with other parts (from its docs, not run by us). Almacam's Nesting Component (PowerNest WS) is another hosted option: an HTTP JSON API for true-shape nesting with holes, several sheets or a strip, and part spacing, by evaluation on request with no public price (from its docs, not run by us).

CutOptim and NestSolver

Two hosted services that were not on this page in October. CutOptim's engine has an MCP endpoint at api.cutoptim.com/mcp and an MIT-licensed package, @cutoptim/mcp, that runs locally over stdio and calls the same hosted API. Of its 10 tools, optimize_nest places "free-form polygon parts on sheets": it takes parts as polygons with holes or as SVG or DXF files and sheets as rectangles or polygons with exclusion zones, and returns the layout as SVG and DXF on request. The others cover rectangular panels, bars and timber, job and usage reads, and four validate tools that check a request without solving it and need no key. Its site says part-in-part nesting, common-line cutting and G-code are not offered, and lists a Studio plan at €49 a month for 3,000 requests, with a 14-day trial of 200 calls. NestSolver runs at mcp.nestsolver.com and needs an account. It nests irregular parts from DXF, DWG and SVG drawings, places smaller parts inside the holes of bigger ones, and exports DXF and SVG. Its free plan gives 5 nests a month of up to 50 parts, and its Bench plan is $19 a month (both from their docs and pricing pages, read 2026-11-22, not run by us).

nestpro

A desktop sheet-nesting CAM program for laser, plasma, oxyfuel and waterjet cutting, written in Rust, with its first release on 2026-11-18. Its README calls it source-available: the licence is PolyForm Small Business 1.0.0, free for businesses with fewer than 100 people and under about US$1 million revenue, with a commercial licence for bigger companies, so it is not open source. nestpro mcp starts a stdio MCP server in which every operation of the app is a tool, and the same operations run as commands without the window, answering in JSON. It imports DXF, DWG, IGES, PDF, ESSI, DSTV and Lantek files and writes CNC programs. It is Windows-first, with a Setup.exe and a portable ZIP, and its README says it also builds and runs on Linux (from its README and releases, read 2026-11-22, not run by us).

Sparrow and spyrrow

Sparrow is a Rust command line and library for 2D irregular strip packing (arXiv 2509.13329): -i input.json -t seconds writes the final layout as SVG and JSON. It solves one strip of fixed width (Sparrow calls it the strip height), not several fixed sheets, and its engine rejects parts with holes. spyrrow wraps it for Python with point lists in and placements out, and no SVG or DXF input. Nestbolt builds on Sparrow and its engine, jagua-rs (from their docs, not run by us for this page).

CLI-nesting

A C++20 command line that reads one JSON file of polygon parts and sheets, with holes, per-part orientations and separate clearances, and writes JSON, DXF and SVG; its README documents placing smaller parts inside other parts' holes. Release archives cover Windows, Linux and macOS; optional OpenCL acceleration is off by default. It reads polygons, not SVG or DXF drawings, so an agent converts the drawing first (from its docs, not run by us).

libnest2d, pynest2d and Packaide

libnest2d is a C++ nesting library that began in PrusaSlicer; pynest2d is Ultimaker's Python binding of its fork, packaged for Cura and shipped through Conan rather than PyPI. Both take polygons built in code and are LGPL-3.0; libnest2d's README says it works well for rectangles and convex polygons, without considering holes and concavities. Packaide is a GPL-3.0 Python library with a CGAL engine that nests SVG shapes onto SVG sheets; its last commit is from 2021 and it is built from source (from their docs, not run by us).

Deepnest, SVGnest and DeepNestPort

Deepnest is a desktop app. Asked in issue #150 about running it from a command line, its maintainer replied in July 2025 that there is no official support. It reads SVG natively and sends PS, EPS, DXF and DWG files to an online converter, converter.deepnest.app, by default. Its 1.6.0 pre-releases of 20 and 21 November 2026 add no command line, API or MCP server; what they do change is on the Deepnest alternative page. SVGnest is a browser app whose JavaScript API (parsesvg, setbin, start) runs inside a page and searches until it is stopped. DeepNestPort, a C# port, ships a desktop app; its source also holds an undocumented console program with a fixed 10-second search (from their docs, not run by us).

sheetnest and ironnest

sheetnest is a Rust library with Python and JavaScript bindings and a CLI whose nest command reads DXF parts, writes DXF and SVG with arcs kept as arcs, and can leave optional micro-joints (uncut tabs), and whose validate command checks overlaps, margins and gaps. It packs rectangular stock or a coil strip of unbounded length, and does not yet place parts inside other parts' holes; the package names in its README returned 404 on 2026-10-20 and again on 2026-11-22, so it builds from source. ironnest 0.6.2 is an MPL-2.0 fork of jagua-rs on PyPI that packs polygons across several sheets from Python (from their docs, not run by us).

MCP servers for rectangular cut lists, such as nestingcalc (its MCP endpoint and sheet calculator), MOACUT and Galvez92/cutlist-mcp, pack rectangles only and are left out (from their docs, read 2026-11-22, not run by us).

When to use the other tool

  • OpenNest if you cut plate on a CNC machine and want DXF, DWG or SVG in and machine G-code out of the same tool, with the cut sequencing, generated lead-ins and G-code post-processors that Nestbolt does not have. Nestbolt writes SVG and DXF cut files (and LightBurn projects in the v0.2.0-alpha.1 preview).
  • Sparrow if your job is a roll or strip of fixed width and your parts have no holes. Nestbolt's README calls it the state of the art for that problem, and Nestbolt runs unmodified Sparrow itself on one-sheet jobs of hole-free parts without defects.
  • CLI-nesting if your parts already exist as polygons in your own pipeline and you want a single JSON-in, files-out command with prebuilt binaries. sheetnest if you want a DXF-in, DXF-out command for rectangular stock or coils and can build it.
  • pyFit if your agent works in Python, your parts are convex or simple single-outline shapes on rectangular sheets, and you want an MCP server that shows layout previews in the conversation, in one small codebase.
  • SmartCut if you need a hosted service with saw-machine exports and labels, and an API key and subscription are fine; Almacam's API if you want hosted true-shape nesting and can arrange an evaluation.
  • NestSolver or CutOptim if you want a hosted MCP service that nests true shapes from your drawings. NestSolver takes DXF, DWG and SVG, places small parts inside holes and has a free plan; CutOptim takes polygons, SVG or DXF, nests onto rectangular or polygon sheets, and is a metered API with a 14-day trial.
  • nestpro if you run a small cutting shop, want a desktop CAM program that an agent can also drive, and its small-business licence fits you.
  • libnest2d or pynest2d if you are already inside C++ or a slicer and only need to arrange polygons on a bed.
  • Deepnest if a person, not an agent, nests the job in a desktop window and wants its common-line merging.

How we checked

  • The searches. We ran seven searches an agent might make, including "Deepnest alternative" and "nesting MCP server for AI agents SVG DXF laser cutting", on 2026-10-20 and again on 2026-11-22. In October Nestbolt appeared in none of them, and the search tool's summaries said twice that no nesting MCP server turned up. In November Nestbolt's Glama listing was the first result for both MCP queries and the summaries named it, with pyFit, SmartCut and CutOptim; Nestbolt appeared in none of the other five, where most results were still directories, aggregators and copies of Deepnest. The queries and results: 2026-11-22 and 2026-10-20.
  • The other tools. Read from their repositories at the commits or pages linked above, plus release pages, package registries, the official MCP registry, Glama and mcp.so, on 2026-11-22. Smithery's search answered every query with an error that day, so it was last read on 2026-10-20, when all four directories were. Nothing of theirs was installed, built or run.
  • Nestbolt. The v0.1.0 release binary was run as described above, on 2026-10-20 and again on 2026-11-22. Its feature claims come from its README and docs; the material numbers come from its published benchmark, which we did not re-run.
  • Refresh. This page is re-checked every 30 days.
